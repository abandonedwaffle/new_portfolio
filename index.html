SimplyCars.in

simplycars.in →

An online database mapping every car variant, engine spec, and trim level in the Indian auto market.

The hard part:

Representing hierarchical car data (manufacturer → model → engine → trim) in Firestore without blowing through free-tier read limits. I solved this by denormalizing trim-engine mappings and building a custom caching layer in vanilla JS so that searching for a car doesn't trigger dozens of database queries.

Battleship

View Code →

A browser-based Battleship game where you play against a computer opponent that uses probability to target and hunt down player ships.

The hard part:

Managing state synchronization and board lockouts during rapid user clicks. I spent days debugging a race condition where double-clicking a grid cell during transition allowed the player to fire twice in one turn, which I resolved by designing a strict state machine to lock grid interactions during the computer's calculations.

Where's Waldo: Street Food Edition

View Code →

A photo-tagging game where players locate famous Indian street food items in a high-resolution, crowded bazaar illustration.

The hard part:

Ensuring coordinate verification worked reliably on responsive layouts. Because the main board image scales dynamically across viewport widths, static pixel coordinate targets broke. I solved this by capturing raw clicks, translating them to percentage offsets relative to the image bounding box, and verifying the ranges against a Node/Express backend.

About

I got into programming because I wanted to understand how the web applications I used every day actually worked. For a long time, I was stuck in tutorial hell—blindly copy-pasting code from video tutorials and pretending I understood it.

That changed when I found The Odin Project. I deleted my half-finished clone apps and started building layouts and logic from scratch, writing my own bugs and forcing myself to trace their origins.

A concrete detail:

While testing SimplyCars.in, I accidentally wrote an infinite loop inside a vanilla state listener. It triggered 40,000+ Firestore reads in under ten minutes and completely exhausted the free tier for the month. It was a stressful, expensive-feeling way to learn the value of rate limiting, debouncing, and validating state loops—but my data-fetching code has been solid ever since.
