Vanilla JavaScript and CSS vs. Framework Bloat

There is an undeniable tactile, mechanical pleasure in writing standard-compliant web pages. No package managers pulling in thousands of nested node modules, no virtual DOM reconciliation passes chewing up mobile CPUs, and no compiled utility class styles that require complex build pipelines.

When you code using vanilla HTML, CSS variables, and native browser APIs, the distance between your thoughts and the rendered pixel is close to zero. The browser is not a compilation target; it is the native canvas.

The Performance Argument

Most web portfolios built with modern frameworks load megabytes of JavaScript just to display static lists of links. This creates a noticeable "stutter" during page loads on sub-optimal networks. By contrast, a vanilla HTML page loads instantly, parses synchronously, and responds to user interactions immediately. 

// Pure browser interaction
const observer = new IntersectionObserver((entries) => {
    entries.forEach(entry => {
        if (entry.isIntersecting) {
            entry.target.classList.add('visible');
        }
    });
}, { threshold: 0.08 });

The CSS and JavaScript used across this entire portfolio is under 15 Kilobytes, including keyframe animations, chassis mode switching, local storage caching, and responsive media rules.

Mechanical Design Feel

Designing with Vanilla CSS allows you to harness custom properties to build a flexible system. By tweaking values at the `:root`, theme switching occurs fluidly using pure browser paint routines. The result is a lightweight site that works everywhere, forever.
